# PR Routes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the Branches page, open PRs from a feature branch into an ordered route of targets (`staging`, then `main`), each one in a dialog filled in from that target's preset.

**Architecture:** A new `src/route.rs` holds the route types, the pure rules (which route applies, template filling, step states, branch protection), and the per-branch PR fetch. A new guard action `Action::CreatePr` runs `gh pr create` through the existing confirm flow. The UI adds a route editor (shared by Settings → Git and a per-repo dialog), a route section in the Branches pane, and an open-PR dialog, all in a new `src/ui/route.rs`.

**Tech Stack:** Rust, the in-repo `rune` / `rune_kit` UI crates, `gh` CLI, serde.

**Spec:** `docs/superpowers/specs/2026-11-19-pr-routes-design.md`

## Global Constraints

- Every UI string goes through `crate::i18n::t` / `tf!`. `python scripts/i18n-check.py` must print `0 without Thai`, so add Thai rows to `assets/i18n/th.tsv` (tab-separated, CRLF like the rest of the file).
- What's shown equals what runs: commands are built only as `gh::Cmd` (see `src/gh.rs` top comment).
- Every PR is opened through `State::request(Action::CreatePr …)` and the guard's confirm dialog. Nothing is sent from the open-PR dialog directly.
- New `Prefs` fields rely on the struct's `#[serde(default)]`, so old config files load unchanged.
- Remote branches appear in the branch list as `origin/<name>` with `remote: true`. Compare and look up by the name without `origin/`.
- Verify with `cargo check` and `cargo test` (the app may be running, which locks `target/debug/sigit.exe` and breaks `cargo build`).

## Review Focus

1. **Branch names with slashes** (`feat/login-v2`, remote `origin/feat/login-v2`): pushed detection, `--head`, and step matching must use the full name after stripping only the leading `origin/`. Test in Task 1 (`head_name`) and Task 6 (`is_pushed`).
2. **Blank and messy comma lists** (`" lead, ,team/x "`) in reviewers, assignees and labels: no empty `--reviewer ""` arguments, entries trimmed. Test in Task 2 (`create_pr_cmd_skips_blank_list_items`).
3. **Titles and bodies with quotes, newlines or `{unknown}`**: passed as single args, unknown placeholders kept as typed. Test in Task 1 (`fill_keeps_unknown_placeholders`) and Task 2 (`create_pr_cmd_keeps_body_as_one_arg`).
4. **`gh pr create` fails** (a PR for that head and base already exists, or no permission): error toast from the guard, the dialog's values not lost, and statuses still reloaded. Test in Task 6 (`create_pr_failure_reloads_statuses`).
5. **The picked branch is a route target or the default branch** (`staging`, `main`): no route section and no Open PR button. Test in Task 6 (`route_hidden_for_targets_and_default`).

### Task 3: Step states

**Files:**
- Modify: `src/route.rs`
- Test: `src/route.rs` tests

**Interfaces:**
- Consumes: `RouteTarget`, `BranchPr`.
- Produces:
  - `#[derive(Clone, Debug, PartialEq)] pub enum StepState { None, Open { draft: bool }, Merged, Closed }`
  - `#[derive(Clone, Debug, PartialEq)] pub struct Step { pub base: String, pub latest: Option<BranchPr>, pub count: usize, pub state: StepState }`
  - `pub fn steps(targets: &[RouteTarget], prs: &[BranchPr]) -> (Vec<Step>, Vec<BranchPr>)`: one `Step` per target, in route order. `latest` is the target's newest PR by `created_at`, and `state` comes from it alone (spec: "a step's state is its newest PR's state"). The second value is the open PRs into bases that aren't on the route ("Also open").
  - `pub fn can_open(steps: &[Step], i: usize) -> bool`: the step is `None` or `Closed`, and it's the first step or the step before it is `Merged`.
  - `pub fn blocked_by(steps: &[Step], i: usize) -> Option<String>`: for `i > 0` with the step before it not `Merged`, that step's base. This feeds "after X is merged" and the CreatePr risk.
